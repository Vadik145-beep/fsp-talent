# Опрос по специализации (T4.1)

Опрос — подсказка перед тестом, баллом не оценивается. Результат: рекомендуемая
специализация, предлагаемый грейд и темы теста. Кандидат может выбрать другую специализацию
и грейд. Код правил: `backend/app/testing/survey.py`, вопросы: `data/seed/survey_questions.json`.

API: `GET /api/testing/survey` — вопросы, `POST /api/testing/survey` — ответы → рекомендация.
Каждая отправка пишет событие `survey` в историю грейда.

## 1. Специализация

У каждого варианта ответа в `survey_questions.json` есть список специализаций, за которые он
«голосует». Голос умножается на вес вопроса:

| Вопрос | Вес | Почему |
|---|---|---|
| q1 «Чем больше всего нравится заниматься?» | 3 | прямой вопрос о предпочтении |
| q3 «Какая задача ближе?» | 2 | конкретная рабочая задача |
| q7 «Где чаще запускаете код?» | 2 | среда работы однозначно указывает на направление |
| q2 «Технологии» (несколько ответов) | 1 за каждый | стек пересекается у разных направлений |
| q5 «Роль в команде», q6 «Что интересно изучать» | 1 | косвенные признаки |
| q8 свободный ответ | 0,5 за каждое ключевое слово | слова вида «Kubernetes», «React», «нейросеть» |

Рекомендуется специализация с наибольшей суммой. При равенстве — та, что выбрана в q1, затем
порядок справочника (backend, frontend, mobile, data_ml, qa, devops). В ответе — три лучших
специализации с долей от общей суммы баллов (`alternatives`). Если ни один ответ не
голосует, рекомендуется backend с пояснением «выберите сами».

## 2. Грейд

Только по опыту (q4): нет опыта → Стажёр, до 2 лет → Junior, 2–5 лет → Middle, больше 5 лет →
Senior. Без ответа — Junior. Это стартовая точка теста (априор движка), итоговый грейд
определяет тест.

## 3. Темы теста

Темы — из справочника тем выбранной специализации, по которым в банке есть рабочие шаблоны.
Варианты ответов и ключевые слова свободного ответа поднимают связанные темы (например,
«Ускорить медленный запрос» → «Базы данных и SQL», «Docker / Kubernetes / Terraform» →
«Контейнеры» и «Инфраструктура как код») с тем же весом вопроса. Сначала темы с наибольшим
весом, затем остальные в порядке справочника, всего до пяти. Таблица связей —
`OPTION_TOPICS` и `TEXT_KEYWORDS` в `survey.py`.

Адаптивный тест всё равно балансирует темы сам (не больше ~трети теста из одной темы),
список тем — объяснение кандидату, что будет в тесте.

## Пример

q1 «Настраивать серверы» (devops ×3), q2 «Docker / Kubernetes / Terraform» (devops ×1) и
«Python» (backend, data_ml, qa ×1), q3 «Выкладка без простоя» (devops ×2), q4 «2–5 лет»,
q8 «Перевели сервисы в Kubernetes, писали Terraform» (devops +0,5 ×2).
Итог: DevOps (7 баллов из 10), грейд Middle, темы: Linux и сети (q1), CI/CD (q3), затем
контейнеры и IaC (стек и слова из текста).

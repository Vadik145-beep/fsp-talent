# 9. Локальная языковая модель (LLM)

ТЗ (3.2) называет преимуществом машинное обучение и обработку естественного языка для разбора
резюме, категоризации и подбора. Организаторы уточнили: предпочтительны открытые модели
с адекватным числом параметров, а при передаче персональных данных команда сама учитывает
152-ФЗ. Поэтому мы не отправляем тексты во внешний сервис: открытая модель работает на нашем же
сервере, в соседнем контейнере.

## 9.1. Модель и где она работает

| | |
|---|---|
| Модель | Qwen2.5-1.5B-Instruct, квантование GGUF Q4_K_M (файл ≈ 1,1 ГБ) |
| Лицензия модели | Apache 2.0 |
| Сервер | llama.cpp (MIT), образ `ghcr.io/ggml-org/llama.cpp:server-b11541` |
| Контейнер | `llm` в `infra/stand/compose.yml` (в dev — профиль `llm` в `docker-compose.yml`) |
| API | OpenAI-совместимый `POST /v1/chat/completions`, адрес внутри сети compose `http://llm:8080/v1` |
| Строгий JSON | в запрос кладётся JSON-схема ответа; llama.cpp строит по ней грамматику, и модель физически не может ответить не по схеме |
| Откуда берётся | файл `qwen2.5-1.5b-instruct-q4_k_m.gguf` из `Qwen/Qwen2.5-1.5B-Instruct-GGUF` (Hugging Face) заранее кладётся на сервер в `/opt/fsp-talent/models` и монтируется в контейнер только для чтения; в dev (профиль `llm`) контейнер скачивает его сам и сверяет SHA-256 (`infra/llm/start.sh`) |

Клиент в бэкенде — `backend/app/nlp/llm.py`. Вызовы асинхронные (`httpx.AsyncClient`) с таймаутом
на каждое место вызова: пока модель думает, бэкенд обслуживает остальные запросы.

## 9.2. Что делает модель

Правило одно: **модель только дополняет результат правил и словарей, оценку кандидата она не
делает.** Категорию по-прежнему определяет адаптивный тест.

| Где | Когда вызывается | Что уходит в модель | Что проверяется | Пометка в ответе API |
|---|---|---|---|---|
| Черновики задач из вакансии (`POST /api/admin/vacancy-tests`) | для тем вакансии, которых нет в банке задач; не больше `LLM_MAX_DRAFTS` черновиков на вакансию | тема, специализация, грейд и слова-признаки темы из вакансии (не весь текст) | схема (4 варианта, номер верного, объяснение) + проверки: варианты разные, текст по-русски, без иероглифов; варианты перемешиваются | `drafts[].origin = "llm"`, `model`, `model_local`; `parser = "llm"` |
| Разбор резюме (`POST /api/candidates/me/resume`) | только если правила оставили поля пустыми | начало текста резюме (до 3000 символов) и схема только с недостающими полями | поля проходят те же справочники, что и у правил; уверенность 0,5 — кандидат подтверждает форму сам | `parser = "llm"` |
| Разбор потребности (`POST /api/matching/needs/parse`) | только если правила не нашли специализацию, грейд или стек; модель свободна | текст потребности (до 2000 символов), схема только с недостающими полями | технология принимается, только если она есть в тексте; грейд — только если в тексте есть требования к опыту | `parser = "llm"` |

Найденное правилами модель не меняет. Метрики разбора на образцах (`docs/validation/`) с моделью
и без неё совпадают: правила резюме и потребности уже находят всё, модель закрывает пробелы на
текстах, где правила промолчали.

Черновик задачи от модели попадает в банк со статусом `draft`. В админке у него пометка
«Написано нейросетью Qwen2.5-1.5B (локально на сервере)», варианты с отмеченным верным ответом
и объяснение. В тесты он идёт только после одобрения администратором — как непроверочная
(пилотная) задача, не влияющая на оценку (см. 2.9).

## 9.3. Персональные данные

Модель работает на том же сервере, что и бэкенд, её порт наружу не открыт (доступна только
внутри сети compose). Тексты резюме и потребностей не передаются третьим лицам и не сохраняются
моделью: llama.cpp держит в памяти только текущий запрос. В черновики задач персональные данные не попадают вовсе: модели
передаются только тема и грейд.

## 9.4. Если модель недоступна

Любая ошибка — модель ещё загружается, контейнер остановлен, таймаут, ответ не прошёл
проверку — означает работу на правилах, как без модели: черновик собирается из словаря тем
(`origin = "vocabulary"`), разбор резюме и потребности — правилами (`parser = "rules"`).
Пользователь не видит ошибки, только честную пометку источника. Если модель не ответила по
первой теме вакансии, остальные темы сразу собираются из словаря, без новых ожиданий.

## 9.5. Как отключить или заменить

- Выключить: `LLM_DISABLED=true` в `infra/stand/.env` и `docker compose up -d backend`; либо
  просто `docker compose stop llm` — бэкенд сразу перейдёт на правила.
- Заменить модель: другой GGUF — положить файл в `/opt/fsp-talent/models` и поменять `-m` у сервиса
  `llm` в `infra/stand/compose.yml`; внешний OpenAI-совместимый сервис —
  `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` у бэкенда.
- Переменные и запуск — в [8.3](08_deployment.md#83-переменные-окружения) и
  [8.4](08_deployment.md#84-стенд-на-сервере-один-сервер-caddy--https).
